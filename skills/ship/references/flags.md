# Separate release from activation

Ship new behavior behind a default-off release flag. Use the project's approved catalog, evaluation seam and activation command.

Name the owner, scope, safe failure outcome and removal condition. Keep permission, consent and entitlements in their authoritative contracts.

Prove disabled, enabled and failure behavior before activation. Read back the runtime's effective value after an authorized change.

Do not infer a live API from a design. Read the project mapping for the landed implementation and current qualification.
