## Local changes

- Second cause-boundary rework: `Unknown`, `Any`, and `Declaration` have no declared child shape. Their immediate object `cause` key is omitted during encoding, but arbitrary deeper objects remain opaque and can still carry a `cause`. Three executable limit tests demonstrate this behavior. Declare nested failure fields with concrete schemas; do not put private diagnostics inside opaque public failure fields. This is not a blanket deep sanitizer for arbitrary values or for secrets in ordinary public fields and messages.
- Build-source fetches now pass the configured remote to the process spawner as `Redacted`. The pinned Node spawner otherwise includes unredacted command arguments in platform-error descriptions, including URL userinfo. The fetch seam checks both executable argument recovery and redacted command display. `SourceFault` and `GitSnapshotError` run local Git queries, not remote fetches; their causes can still contain local command/path diagnostics. Build failures print through local/CI runners, not Worker responses.
- Tracing remains a separate diagnostic boundary. CLI composition installs no exporter. Worker traces default off; when enabled, the registered Cloudflare tracer can export the first failure message in span status. The private tracer wrapper discards attributes/events/links but does not sanitize `end` status. The older explicit native tracer adapter exports only the success/failure classification. This packet does not claim that stripping failure responses redacts every trace exporter.
- The tap-before-narrowing exemption now requires a callback that reads its error parameter, or the direct `Effect.logError` function. A zero-parameter tap or an unused parameter no longer excuses dropping the error. This is a syntactic read check, not proof that every tap logs the error.
- Verification for the second rework: each of the seven deploy logging sites captures a planted credential with a test logger; the four remote surfaces exercise nested named and index-signature failures, arrays, tuples, unions, and suspension. HTTP, RPC, and MCP assert one cause log per failed call. Mutation runs disable child recursion, the tap read check, and safe logging independently; they expose four transport failures, the new lint fixture failure, and five receipt logging failures respectively. Fix/override counts for the original 79 findings stay at 47/32 (44 cause-preserving fixes plus three domain/diagnostic repairs); this rework adds no cause-rule override.

- 2026-11-16, cause boundary rework of `900ffeec`: `wireFailureSchema` in `packages/capability` owns the encoded failure boundary for HTTP, RPC (including contract-only clients), MCP toolkit tools, and code-mode invocation. One recursive schema traversal removes declared `cause` fields from both the public schema and encoded values, including nested objects, index-signature values, arrays, tuples, unions, and suspended recursive schemas. It preserves the tag and public fields and logs the original top-level cause on the server once before encoding. Optional causes stay absent on decode; required `Schema.Defect()` causes decode to a private-data-free `null` placeholder. Local `to-command` failures retain diagnostic causes: the CLI runs in the operator's process and has no remote error response. It does not pass CLI failures to the wire adapters.
- The rework keeps credential-bearing provider/profile failures opaque, including worker deployment reads, rollback writes, and rollback-runner translations. Provider worker attributes also stay opaque because their decode errors can include deployment secrets. `DeployStepError`, `RollbackFailed`, and approval failures declare no cause. Receipt schemas already allowlist persisted facts and omit extra causes; seven receipt/config/check translations log only an allowlisted diagnostic before narrowing instead of attaching the source. The logger keeps the schema-error tag (or a fixed boundary tag), step, fixed reason, and schema paths. Dynamic path keys become `<key>`; it never logs the error, input, profile, cause, or formatter message. Receipt privacy tests exercise all four write paths, including nested receipts, and keep reason, step, and keys. A rollback seam test resolves planted API/OAuth tokens from `Credentials`, injects a credential-bearing provider failure, and verifies that restore/check failures and the written rollback receipt omit it. Worker provider errors use explicit privacy overrides rather than assuming a provider-error redaction guarantee.
- Prompt evidence at `effect@4.1.4`: `src/cli/Prompt.ts` types `run` with `Terminal.QuitError` and maps terminal-input errors to `new Terminal.QuitError({})`; `src/Terminal.ts` declares that error with no fields.
